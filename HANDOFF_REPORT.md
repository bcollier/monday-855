# Handoff Report

## What did you read first, and did it help?

I read the SPEC.md file, it was a description of a game about a door person letting people inn. It overall did a strong job of what the goal of the game was, what the vibe was supposed to feel like. It was really helpful to hear what the creator was looking for, more about the door mechanics, and how the game mechanics would work.

## Was the spec clear? Could you tell what the author wanted? Were the acceptance criteria checkable or vague?

Overall it was very good, one minor thing was that the section on "the door" was a big vague, it actually wasn't clear to me upon reading that this was going to be a rotating door, I assumed it would be a standard door a doorperson would open. The acceptance critera was actually more detailed in the readme file (it had numbered and prioritized criteria), the SPEC was lacking some details that were present in the readme.

## What made the code easy to work with?

*Be specific: "good comments" tells the author nothing, "the collision logic was one function with a docstring stating its assumptions" tells them everything.*

The structure of the code was quite simple, one folder for Javascript and one for tests. The names of all the javascript code files reflected well the various parts of the application so there were not any giant vague files. The code was readable and well documented.

## What cost you time?

*Again specifically (e.g. cryptic names, a 400-line single file, an unstated environment assumption, a documented feature that wasn't there).*

It took a lot of prompting and gameplay loops to get the game where it was appropriately difficult (adding a tutorial mode) for new players but also ramps up to be difficult as the clock gets to 9am. Early on I could lose immediately. Some of the mechanic like how to "hold" for "bad guys" was a little vague on how it was supposed to work.

## What one thing would you ask the author to do differently next time?

It wasn't clear to me what would make this game "fun to play", like when I went to add game mechanics to make the game more dynamic, there wasn't a lot of guidance on where to take things. For some reason in your spec you said that any sound is out of scope. I'm not sure whether that was a preference, or a hard limit, or why?
